## Деплой на Vercel

1. Создайте GitHub-репозиторий и загрузите в него проект из папки `coffee-page`
   (не добавляйте `node_modules`, `.next` или `data/leads.sqlite`).
2. Войдите в [Vercel](https://vercel.com), выберите **Add New → Project**,
   импортируйте этот GitHub-репозиторий и оставьте настройки Next.js по
   умолчанию. Убедитесь, что корень проекта указывает на папку с `package.json`.
3. Для проекта укажите Node.js 22 или новее, затем нажмите **Deploy**. Vercel
   сам выполнит установку зависимостей и `npm run build`. После успешной сборки
   откройте выданный адрес `*.vercel.app`.
4. Для будущих обновлений достаточно отправить изменения в подключённую ветку
   GitHub: Vercel автоматически создаст новый деплой. Перед публикацией проверьте
   в настройках проекта Production Domain и домен, который используете.

### Важно о заявках

Сейчас API сохраняет заявки в SQLite по пути `data/leads.sqlite`. Файловая
система Vercel не подходит для постоянной SQLite-базы: файл может быть
недоступен для записи или исчезнуть между запусками функций. Не принимайте
реальные заявки на Vercel, пока хранение не будет переведено на постоянную
внешнюю базу данных (например, Postgres) и не будет проверено повторной
отправкой и чтением заявки. Одна только переменная `LEADS_DB_PATH` проблему
постоянства не решает. Текущую команду `npm run leads` можно использовать
только там, где доступен соответствующий файл базы.

## Lighthouse для мобильной версии

Запускайте аудит по Production URL после деплоя, а не по адресу разработки.
В Chrome:

1. Откройте главную страницу `*.vercel.app` в окне инкогнито.
2. Откройте DevTools (`F12`) → вкладку **Lighthouse**.
3. Выберите режим **Navigation**, категорию **Performance** (для полного отчёта
   можно отметить также Accessibility, Best Practices и SEO), устройство
   **Mobile**, затем нажмите **Analyze page load**.
4. После завершения сохраните отчёт через кнопку выгрузки вверху отчёта
   (HTML или JSON). Для подтверждения результата также сделайте скриншот
   страницы отчёта, где видны выбранное устройство и оценки.

Передайте HTML/JSON или скриншот вместе с адресом сайта. Для сравнимого замера
зафиксируйте дату, URL и результаты; повторите аудит 2–3 раза на стабильном
соединении, поскольку сетевые условия могут менять оценки. Отчёт Lighthouse —
это замер производительности и качества страницы, он сам по себе не проверяет,
что API сохраняет заявки в постоянную базу.
